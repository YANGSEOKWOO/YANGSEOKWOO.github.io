# /graph — 지식 그래프 갱신

블로그의 글들을 분석해 **글 사이의 연결(엣지)**을 계산하고 `assets/graph-data.json`을 갱신한다.
시각화 페이지는 `/graph/`(`graph.html`)이며, **노드는 Jekyll이 `site.posts`에서 자동 생성**한다. 따라서 이 커맨드는 **엣지만** 계산하면 된다.

## 절차

1. `_posts/` 안의 모든 `*.md` 글을 읽는다. (`_posts/`가 없거나 비어 있으면, 빈 엣지로 `graph-data.json`을 쓰고 글이 없다고 알린다.)
2. 각 글에서 다음을 파악한다:
   - **slug** — 파일명에서 날짜 접두사와 `.md`를 뺀 것. 예: `2026-06-19-hash-table.md` → `hash-table`. (그래프 노드 id가 이 slug다.)
   - 프론트매터의 `category`, `tags`, `title`.
3. **엣지를 만든다.** 두 글을 연결하는 근거는 다음 우선순위로:
   1. **본문의 내부 링크** — `](/cs/hash-table/)` 같은 마크다운 링크나 `[[hash-table]]` 형태. 링크의 마지막 경로 조각(slug)을 실제 글과 **대소문자 무시**하고 매칭한다. (가장 강한 연결)
   2. **공유 태그** — 같은 태그를 가진 글끼리. `reason`에 `tag: <태그>`로 표기.
   3. **명확한 주제 연관** — 위 둘에 안 걸려도 내용상 분명히 이어지는 글이면 연결하되, `reason`에 한 줄로 근거를 적는다. (억지 연결 금지 — 애매하면 만들지 않는다.)
4. 엣지는 **무방향**으로 취급해 중복 제거한다 (A↔B와 B↔A는 하나).
5. 양 끝이 **모두 실제 존재하는 글**인 엣지만 남긴다.
6. `assets/graph-data.json`을 다음 형식으로 덮어쓴다:
   ```json
   {
     "generated": "YYYY-MM-DD",
     "edges": [
       { "from": "<slug-a>", "to": "<slug-b>", "reason": "본문 링크" }
     ]
   }
   ```
   `generated`는 오늘 실제 날짜.

## 마무리 보고

다음을 요약해 알린다:
- 글 수, 엣지 수, 카테고리별 글 개수
- **고립된 노드**(연결이 하나도 없는 글) 목록 — 이런 글은 "관련 글" 링크를 보강하면 좋다고 제안
- `bundle exec jekyll serve` 후 `/graph/` 페이지에서 확인할 수 있다고 안내
